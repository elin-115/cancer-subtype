## 3. train에서 확인한 사실 (test는 보지 않음)

- 모든 유전자가 WT(변이 없음)인 환자 94명
- 한 칸에 변이가 여러 개 들어 있는 경우 약 2만 2천 칸 (예: `Q369* I368N`)
- 변이 종류: missense 약 16만 5천 개, silent 약 6만 7천 개, nonsense 약 1만 3천 개, frameshift 약 1만 개
- 환자 1명의 변이 수가 암마다 크게 다름: 자궁내막암(UCEC) 평균 180개, 백혈병(LAML) 3.4개
- KRAS, NRAS, KEAP1, SMAD4, STK11 등 유명한 암 유전자가 데이터에 없음 → 경로 목록에서 **데이터에 있는 유전자만** 사용
- 강한 핫스팟: BRAF 600번(갑상선암·피부암), IDH1 132번(뇌종양), SPOP(전립선암)

## 4. 만들 피처 (합친 우선순위)

모두 환자 한 명의 데이터 안에서 계산하는 피처는 Data Leakage 걱정이 없습니다. 정답(SUBCLASS)을 보고 만드는 피처는 **CV fold 안에서** 만들어야 합니다.

| 순서 | 피처 | 계산 방식 | 근거 | 상태 |
|---|---|---|---|---|
| 1 | 핫스팟 여부 | 행 단위 (train 빈도로 선택) | Chang 2016, train | 완료: N≥10, 152개. 베이스라인 XGB 0.4069 → 0.4129, 도엽 v1 앙상블 0.4359 → 0.4406 (XGB에만 추가). N≥5(573개)는 0.4134로 차이 없음 |
| 2 | 변이 종류별 개수 (missense, silent, nonsense, frameshift) | 행 단위 | Jiao 2020, OncoKB 아이디어 | 도엽 v1에 포함. v2에 추가 시 CV 0.414 → 0.4201 ⬆️ (6절 B) |
| 3 | 진짜 변이 개수 (한 칸 여러 개 모두 세기) | 행 단위 | train | 반영됨: 도엽 v1 `Mutation_Token_Count` (기존 `n_mut`은 유전자 수) |
| 4 | 경로별 고장 유전자 수 | 행 단위 | Sanchez-Vega 2018 | 효과 없음: 0.414 → 0.4094 ⬇️ (6절 A). 최종에서 제외, 발표 설명용으로만 사용 |
| 5 | 드라이버 변이 수 / 나머지 변이 수 | 행 단위 | Bailey 2018 | 효과 없음: 0.414 → 0.4092 ⬇️ (6절 E). PANCAN 목록만 사용 |
| 6 | 아형 마커 점수 | **fold 안에서** train 부분으로 마커 선정 | Hoadley 2018 | 효과 없음: 0.414 → 0.4026 ⬇️ (6절 F) |
| 7 | 유전자별 끊김 표시 (nonsense·frameshift) | **fold 안에서** 10명 이상 끊긴 유전자 선정 | OncoKB 아이디어, 박종부 제안 | 효과 있음: 0.414 → 0.4209 ⬆️ (6절 D) |
| 8 | 핫스팟 개수 | 행 단위 | 새 아이디어 | 애매: 0.414 → 0.4186 (6절 C). 다른 피처와 합치면 도움 |

참고: 도엽님 v1이 이미 "변이 토큰 + 변이 부담(종류별 비율 포함)"을 넣어서 CV가 0.407 → 0.440으로 올랐습니다. 2·3번은 v1에 들어 있어서 따로 실험하지 않습니다.  
실험 노트북: `02_v2_hotspot.ipynb`(1·4번), `03_v1_핫스팟_비교.ipynb`(v1 + 1번)

## 6. 파생변수 실험 결과 (11/9, 김지연)

### 6-1. 실험 방법

**기준 모델 (v2-N5, 리더보드 0.3236)**
- XGBoost 하나 (트리 300개, 깊이 6, 트리마다 유전자 30%만 사용), 소수 아형 가중치(balanced)
- 피처: 유전자별 변이 0/1 4,384개 + 환자별 변이 유전자 수(`n_mut`) 1개 + 핫스팟 0/1 573개(train에서 5명 이상 나온 "유전자_자리")

**비교 방법**
- 기준에 파생변수를 **하나씩만** 더해서 5-Fold 교차검증 Macro F1을 비교함 (StratifiedKFold, seed 42, 모든 실험에서 fold 동일)
- 효과가 있어 보이는 것만 다시 합쳐서 한 번 더 비교함

**흔들림 확인**
- 같은 설정을 6번 돌리면 CV가 0.4125~0.4176으로 흔들림 (평균 0.414). XGBoost 병렬 계산 때문에 생김
- 그래서 **0.418보다 높아야 "효과 있음"** 으로 판단함

**누수 방지**
- A·B·C·E는 환자 한 명의 행 안에서만 계산함
- D·F는 train 부분을 보고 기준을 정해야 해서 **fold 안에서** 만듦. test는 그 기준으로 변환만 함

|---|---|---|---|---|
| A | 경로별 고장 유전자 수 | 10 | 신호 경로 10개마다 변이 있는 유전자 수 | Sanchez-Vega 2018 |
| B | 변이 종류별 개수·비율 | 14 | missense, silent, nonsense(`*`), frameshift(`fs`) 등의 개수·비율, 변이 표기 수, 여러 변이가 든 칸 수 | 도엽 v1, 박종부 제안 |
| C | 핫스팟 개수 | 1 | 환자가 가진 핫스팟 변이 수 | 새 아이디어 |
| D | 유전자별 끊김 표시 | 약 370 | 그 유전자에 nonsense·frameshift가 있으면 1 (train fold에서 10명 이상 끊긴 유전자만) | OncoKB 아이디어, 박종부 제안 |

### 6-3. 결과

**하나씩 추가** (기준: 평균 0.414, 범위 0.4125~0.4176)

| | 파생변수 | CV | 판단 |
|---|---|---|---|
| A | 경로 | 0.4094 | ⬇️ 제외 |
| B | 변이 종류 | **0.4201** | ⬆️ 효과 있음 |
| C | 핫스팟 개수 | 0.4186 | ↗️ 애매 |
| D | 끊김 표시 | **0.4209** | ⬆️ 효과 있음 |
| E | 드라이버 | 0.4092 | ⬇️ 제외 |
| F | 아형 마커 | 0.4026 | ⬇️ 제외 |

**합쳐서 추가**

| 조합 | CV | 기준 대비 |
|---|---|---|
| B + D | 0.4243 | +0.010 |
| **B + C + D** | **0.4293** | **+0.015** |

**아형별 변화 (B+C+D)**
- 많이 오름: LUSC +0.15, CESC +0.12, BLCA +0.09, COAD +0.07
- 떨어짐: LGG −0.14, KIRC −0.11 → GBMLGG·KIPAN과 변이가 같은 환자가 많은 아형이라, 쌍 안에서 예측이 옮겨간 것 (라벨이 겹치는 문제)

### 6-4. 해석

- **효과 있던 것 (B, D)은 변이의 "종류"를 알려주는 피처**  
  같은 유전자라도 글자 하나 바뀐 것(missense)과 단백질이 끊긴 것(nonsense, frameshift)은 의미가 다르고, 암마다 변이 종류 비율도 다름
- **효과 없던 것 (A, E)은 이미 있는 0/1 열을 더하기만 한 피처**  
  모델이 가진 정보를 묶은 것이라 새 정보가 없음. Jiao 2020도 "드라이버 정보를 넣으니 정확도가 떨어졌다"고 보고함 ([6_1](./6_1_규제윤리_박종부.md) 4-2절)
- **오히려 떨어진 것 (F)은 정답을 보고 만든 피처**  
  fold 안에서 만들어 누수는 없지만 train 부분에만 맞춰짐. test가 train과 다를 가능성까지 생각하면 리더보드에서 더 위험함

### 6-8. v8A(중복 정리 + 2단계) 위에 후보 피처 얹기 (11/11, 김지연)
- 방법: 김도엽 `07_v8_service_model.ipynb`의 v8A(1단계 XGBoost + 2단계 로지스틱 회귀, fold 안 중복 정리)를 그대로 옮긴 틀에 하나씩 추가. 일반 5-Fold(StratifiedKFold, seed 42), 원래 26개 라벨 Macro F1
- 기준 재현: CV 0.4294 (도엽 노트북 0.4261, 차이는 실행 간 흔들림 범위). 재현 제출 파일은 도엽 파일과 예측 87% 일치 → 제출은 도엽 원본 파일 기준

| 추가한 것 | CV | 기준 대비 | 기준보다 오른 fold |
|---|---|---|---|
| D 유전자별 끊김 0/1 (fold 안 10명 이상) | 0.4320 | +0.0027 | 3/5 |
| H BLOSUM62 심한 치환 0/1 (fold 안 10명 이상) | 0.4297 | +0.0003 | 2/5 |
| 불균형 가중치 0.7 | 0.4284 | −0.0010 | 1/5 |
| 핫스팟 기준 N≥10 | 0.4270 | −0.0024 | 2/5 |
| S silent 변이 제외 | 0.4127 | −0.0167 | 0/5 |

- 해석: 다섯 개 모두 흔들림(fold 간 ±0.01) 안이거나 하락. D가 가장 높지만 v2-N5 위에서도 CV +0.006 → 리더보드 −0.004였던 피처라 제출 근거가 약함. 피처 추가로는 v8A를 확실히 넘는 후보가 없음 → 남은 제출은 v8B(도엽) 확인과 v8A 유지가 우선

**2단계(묶음 안 세부 아형) 다듬기** — fold마다 1단계 XGBoost는 한 번만 학습하고 2단계 로지스틱 회귀 설정만 바꿔 비교 (1단계 흔들림 제거)

| 2단계 설정 | CV | KIPAN / KIRC / GBMLGG / LGG F1 |
|---|---|---|
| 기준 C=0.005 (v8A) | 0.4294 | 0.272 / 0.376 / 0.350 / 0.577 |
| C=0.05 | 0.4238 | 0.211 / 0.311 / 0.344 / 0.564 |
| C=0.5 | 0.4108 | 0.164 / 0.165 / 0.308 / 0.454 |
| C=0.002 · 0.001 · 0.0003 | 0.4294 · 0.4294 · 0.4295 | 기준과 거의 같음 |
| + 핫스팟 0/1, C=0.001 | 0.4301 | 0.277 / 0.372 / 0.358 / 0.586 |

- 규제를 약하게 하면 개별 환자를 외워서 크게 하락. 0.005보다 강하게 해도 변화 없음 → v8A의 2단계는 이미 최적 근처
- 핫스팟을 더하면 GBMLGG·LGG가 조금 오르지만 전체 +0.0007로 흔들림 안. 제출 후보로 올리지 않음
- train에서 라벨이 다른 중복 조합은 KIPAN–KIRC 272쌍, GBMLGG–LGG 173쌍, LGG–THCA 1쌍뿐이라 중복 정리를 넓힐 곳도 없음 → v8A 구조 안에서 더 짜낼 여지는 작음

### 6-9. 아미노산 치환 패턴 피처 (11/11, 김지연) — v8A 위
- 아이디어: 암마다 변이를 만든 원인(담배·자외선·APOBEC 등)이 달라 남기는 치환 패턴이 다름 (mutational signature). 염기 정보는 없지만 아미노산 치환(E→K, P→S 등)에 흔적이 일부 남음
- PAIR: 환자의 missense 중 각 치환쌍(원래→바뀐 아미노산)의 비율, 분모 +1로 변이가 적은 환자는 0 쪽으로 줄임. 학습 fold에서 30명 이상에게 나온 치환쌍만 사용 (라벨 안 씀). 행 안에서만 계산, test는 추론만
- SPEC: 원래/바뀐 아미노산 비율 20+20 + silent 아미노산 비율 20

| v8A 위에 추가 | CV | 기준(0.4294) 대비 | fold별 차이 |
|---|---|---|---|
| PAIR | **0.4650** | **+0.036** | +0.012 / +0.040 / +0.040 / +0.064 / +0.025 (5/5 상승) |
| SPEC + PAIR | 0.4461 | +0.017 | 5/5 상승 |
| SPEC | 0.4372 | +0.008 | 3/5 상승 |

- PAIR에서 오른 아형: CESC 0.15 → 0.38, TGCT → 0.55, STES → 0.54, LUSC → 0.48. 떨어진 아형: DLBC 0.50 → 0.30 (환자 수가 적음)
- 제출 파일 `submission_v8A_PAIR.csv` (도엽 v8A와 예측 57% 일치). 11/12 10:06 제출 → **리더보드 0.3546** (v8A 0.3322 대비 +0.022, 팀 최고). 형제 라벨 없이 단독 확인
- 스크립트: `scripts/v8x.py v8A_PAIR PAIR SUBMIT` (도엽 v8A를 옮긴 틀, 옵션 하나씩 띄어 적기)

### 6-11. 텍스트 마이닝 (TF-IDF + 로지스틱 회귀) 섞기 (11/12, 김지연) — 1위 팀 힌트
- 힌트: 1위 팀이 로지스틱 회귀 + LGBM + 텍스트 마이닝을 썼다고 함
- 방법: 환자 한 명의 변이 목록을 문장처럼 보고 단어로 쪼갬 → `BRAF`, `BRAF_V600E`(변이 표기 그대로), `BRAF@600`(위치). TF-IDF(2명 이상에게 나온 단어, sublinear)로 바꿔 로지스틱 회귀(balanced)에 넣고, v8A+치환쌍 XGB 확률과 섞은 뒤 2단계 판정은 그대로 함. TF-IDF·회귀 모두 학습 fold(중복 정리 후)로만 학습
- 결과 (같은 5-Fold, 섞는 비율 w = 로지스틱 쪽)

| 설정 | CV | 비고 |
|---|---|---|
| 섞지 않음 (v8A + 치환쌍) | 0.4650 | 리더보드 0.3546 |
| C=1, w=0.7 | 0.4803 | |
| **C=3, w=0.7** | **0.4892** | 5/5 fold 상승 (+0.032, +0.017, +0.028, +0.008, +0.035) |
| C=10, w=0.7 | 0.4799 | |
| C=3, w=0.85 | 0.4714 | |
| 로지스틱 회귀만 (w=1) | 0.41 안팎 | 혼자서는 XGB보다 약함 → 섞어야 오름 |

- 많이 오른 아형: 방광암 0.41 → 0.47, 급성 골수성 백혈병 0.53 → 0.59, 갈색세포종 0.29 → 0.35, 림프종 0.30 → 0.37, 전립선암 0.32 → 0.37. 떨어진 아형: KIRC 0.39 → 0.34
- 제출 파일 `submission_v8A_PAIR_TF.csv` (치환쌍 버전과 82.5% 일치). 주의: 과거 앙상블은 CV만 오르고 리더보드는 떨어졌음(묶음 CV 0.456 → 0.2982). 이번엔 변이 표기 단위 단어를 새로 쓴다는 점이 다름
- 스크립트: `python scripts/v8x.py v8A_PAIR_TF PAIR TFC3 TFW0.7 SUBMIT`, 비율 비교는 `WS=… CS=… python scripts/v8x.py 이름 PAIR TFGRID`
