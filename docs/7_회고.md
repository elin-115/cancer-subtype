# 프로젝트 회고

- 작성: 김지연 (11/13, 발표 후)
- 1·2등 팀 발표 자료와 비교해 정리함
- 최종 제출: v12 + STACK, 시드 3개 평균, 리더보드 0.4072 (형제 규칙 미사용)

---

## 1. 놓친 것·간과한 점

**규정 확인**
- 형제 규칙 허용 여부를 공식적으로 늦게 확정함. 운영진 답변(허용)이 리더보드 마감 이후(11/13 14:05)에 와서 결국 안전한 쪽을 골랐음
- 규정 판단이 늦으면 그 자체가 점수 손해라는 걸 배움

**피처 (생물학적 해석 부족)**
- 변이의 **종류**를 덜 봤음. 1·2등 모두 침묵·넌센스·frameshift 비율, 절단형 토큰(`APC__TRUNC`), 아미노산 성질 그룹 변화(−→+ 등)를 넣었음
- **돌연변이 서명**: 치환쌍은 만들었지만 원인(자외선은 C>T, APOBEC은 E>K·E>Q)으로 묶어 해석하지 않음
- **유전자별 암종 분포 점수**(1등 중요도 37.6%, fold 안에서 계산한 타깃 인코딩)를 시도하지 않음

**앙상블**
- 혼자 점수는 낮아도 다른 각도에서 보는 모델을 5%나 20%만 섞는 실험을 XGB+LR 이후 더 밀어붙이지 않음

**검증과 리더보드**
- S3와 S7은 85행만 다른데 리더보드가 0.007 벌어질 만큼 public LB 노이즈가 컸음. 이를 늦게 깨닫고 LB 숫자에 끌려다닌 시간이 있었음
- 채택 기준이 "CV가 오르면"이었음. 2등은 "시드 두 개 모두 올라야 채택"으로 노이즈를 걸렀음

**결과 해석**
- **이론상 상한**(같은 프로필에 다른 정답이 붙은 8.2%는 못 맞힘, KIRC 최대 F1 0.586)을 계산하지 않음. 모델의 한계와 데이터의 한계를 구분해 보여주지 못함
- 상위 3개 적중률, 묶음(KIPAN/KIRC) 단위 F1, 확신 구간별 정확도처럼 **의료진이 바로 이해하는 숫자**가 부족했음
- F1이 낮은 암종(THYM, SARC)의 원인을 논문으로 추적하지 않음. 1등은 THYM 핵심 유전자 GTF2I가 컬럼에 없다는 점을 짚었음

**데모**
- 진짜 모델을 연결하는 데 집중하느라 설명 문구, 리포트 같은 사용자 경험(UX)이 약했음

---

## 2. 나아진 점

- **누수 관리 원칙을 끝까지 지킴**: test EDA 안 함, 기준값은 train에서만 계산, 표기 형식 규칙은 제출에서 제외
- **재현성**: 최종 노트북과 데모가 제출 파일과 2,546행 100% 일치
- **진짜 모델로 데모**: 형제 규칙 없는 S3라 실제 환자에게 그대로 쓸 수 있음. 모델만 비교하면 1등보다 높음(0.4072 대 0.3943)
- **CV와 LB 차이의 원인 규명**: 과적합이 아니라 test 표기 형식과 변이 수 차이라는 걸 밝히고 표기 통일로 일부 해결
- **기록**: 실험 문서, 타임라인, 예상 질문, 발표 대본까지 남겨 회고와 포트폴리오로 바로 쓸 수 있음

---

## 3. 앞으로 주의할 점

- **규정 문의는 첫 주에 서면으로 하고, 답이 없으면 두 버전을 모두 준비**
- **리더보드보다 CV**: 시드 2개 이상에서 모두 올라야 채택, 리더보드는 확인용으로만 사용
- **발표와 데모 시간을 처음부터 따로 떼어두기**: 모델 마감과 발표 준비가 겹치지 않게 함

---

## 4. 더 노력할 점

- **도메인 지식**: 변이 유형, 돌연변이 서명, 암종별 대표 유전자를 먼저 공부하고 피처로 연결하기
- **결과를 이야기로 만드는 힘**: 상한, 오류 분석, 확신도, 임상 연결(치료제)까지 이어서 보여주기
- **UX**: 숫자를 "왜 이런 결과인지" 설명하는 문장으로 바꿔 보여주기
